## Phase V3.2 · Prediction reliability

Build a reproducible diagnostics report from the frozen benchmark and the eligible rows in `data/recovery-v1/final-locked/`. The frozen JSON contains aggregate/error quantiles and geometry, alpha, Re and camber slices. For missing slices, pair saved eligible labels with a read-only run of the frozen ONNX graph, reproduce published aggregates and leave the one-use evaluation artifacts untouched. Report counts, MAE, signed bias and absolute-error quantiles by geometry, m, p, t, alpha, Re and true CL/CD. Separate symmetric rows from cambered-position bins, publish the bin definitions and failure denominators, and use geometry-grouped resampling for diagnostic sampling variation when sample size permits. Display model version, observed MAE, interpolation and documented difficult conditions in an expandable panel.

Start applicability estimation with a compact index of accepted training rows from `train.parquet`, grouped by geometry and keyed to model and training-data hashes. Compute nearest accepted neighborhood distance with manifest-range normalization for geometry, alpha and log Re, explicitly treating the symmetric family so unused p creates no artificial distance. Compare against simpler geometry-only distance on development evidence. Choose and record threshold and metric with leave-one-geometry-out training comparisons and the archived development panel. An in-bounds sparse design can still receive coefficients with a limited-coverage warning. If the index fails to load, report coverage unavailable. Use the terms nominal bounds and nearby training coverage, and report the independent evaluation only at the aggregate or slice level supported by its samples. Omit any score framed as a probability.

Recommendation for the first release is applicability and observed errors. The 33 training geometries fitted the model, eight development geometries informed selection, three earlier test geometries became diagnostic, and the eight final geometries are consumed. None form a fresh calibration and independent test pair. Group bootstrap would add runtime or require offline distillation, and ensemble spread would still need independent calibration. A fixed residual interval is cheap but inherits each calibration panel's operating-point mix. If approved separately, prefer group-aware split conformal with a predeclared geometry sampling distribution and a defined target, such as simultaneous coverage of a fixed operating grid using one max-residual score per geometry. Standard 90% split-conformal ranking needs at least nine exchangeable calibration groups for a finite quantile and substantially more for practical characterization. Freeze target, score, sample size, acceptable interval widths and coverage-test protocol before generating labels. Report coverage, widths, between-geometry variation and uncertainty on independent groups, including hard slices. If assumptions, sample size or width/coverage criteria fail, omit intervals. [Hierarchical conformal methods](https://arxiv.org/abs/1809.07441) · [Conformal foundations](https://arxiv.org/abs/2411.11824)

Exit criteria:

- Diagnostic report and plots reproduce published overall MAE within `1e-6` in each coefficient, include all requested axes and retain rejected-case accounting. Data provenance and hashes are verifiable. The accepted model and benchmarks remain byte-identical.
- Domain/coverage tests cover exact and just-outside bounds, Re interpolation, symmetric canonicalization, sparse and unseen-but-near geometries, absent index and deterministic scores. Versioned index uses eligible training data only. Freeze candidate safeguards from development evidence before optimizer verification.
- The UI differentiates unavailable, out-of-bounds, nominal and limited-coverage states. Reports carry sample counts and scope. Calibrated uncertainty is optional and gated by the independent protocol above. Run shared regression and accessibility checks.

## Phase V3.3 · Constrained design optimization

Start with seeded differential evolution and an equal-budget seeded random-search baseline. Fix Re, constrain alpha or let it vary within the selected bounds, and constrain m, p and t inside the manifest. Treat symmetric geometry as a distinct feasible case and canonicalize before deduplication. Rank feasible candidates by maximum CL/CD, minimum CD with CL at or above the requested minimum, or maximum CL with any configured thickness constraint. Record attempts, coverage rejections, submitted model rows and valid results separately. Refuse nonfinite outputs and tiny CD before division. Set a stricter optimization-only CD floor and broad coefficient plausibility bounds from training/development evidence, with a published rationale and tests. Reject candidates flagged as sparse by the V3.2 search policy. Preserve the baseline snapshot, label infeasible baseline comparisons explicitly, and report improvement only where it is defined. Show a diverse shortlist, progress, history, overlays and parameter deltas. Apply and revert through the Studio's validated design state. Label results **Surrogate-predicted candidate**.

Runtime feasibility is promising. The browser artifact recorded desktop p95 of 0.5 ms for a 17-row warm batch. Production already runs the accepted graph through ONNX Runtime Web 1.31.1's WASM proxy, and the separate affine fixture demonstrates same-origin module worker loading. Those results cover neither the optimizer's full graph worker integration nor mobile hardware and WebKit behavior. First evaluate a lazy dedicated optimizer worker that computes proposals and scores and delegates bounded batches to the existing proxy-backed session via an async bridge. Keep one session and one runtime transfer, prioritize interactive work between batches, and measure the cost of input packing and messaging. If budgets or compatibility fail, evaluate owning the single shared session in a dedicated worker with `proxy=false` and one WASM thread. Require the same model parity, reset/retry behavior and static asset URLs. If neither passes, disable search on affected profiles while Studio inference stays available. Use run IDs, bounded batches and cancellation checks before submission and after completion. [ONNX worker deployment](https://onnxruntime.ai/docs/tutorials/web/deploy.html) · [Runtime flags](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)

Export versioned JSON with full-precision design and flow, baseline, shortlist, objectives, constraints, seed, counts, predicted CL/CD, model hash and domain/coverage version. An offline CLI validates the schema and runs pinned XFOIL 6.99 with one fresh process per point, 160 panels, Mach 0, Ncrit 9, transition limits of 1, 150 iterations and 20 s timeout from the recovery config. Record each case's settings, raw hashes, convergence, eligibility and coefficient deltas. Compare feasible solver and surrogate ranks and mark rejected or failed cases with missing solver values. Include a fresh shortlist verification set sized and approved with this phase to evaluate constraint misses and ranking reversals. Keep those observations separate from the historical benchmark and any uncertainty calibration.

Exit criteria:

- Tests cover all objectives, fixed and bounded alpha, physical/coverage guards, numerical invalids, duplicate and infeasible candidates, deterministic seeds, budget accounting, cancellation during initialization and in flight, and no state update from an old run. Apply/revert and export preserve the original design and predictions with their inputs. A cancelled or exhausted run reports its true count and feasible results.
- Compare differential evolution and random search on at least three predeclared cases and three seeds per case at equal model-row counts. Record effectiveness and failures. Browser results match the existing goldens within `1e-5` per coefficient. Verify performance and responsiveness against the optimizer budgets below on the production static export.
- Python fixture tests and an actual bounded XFOIL replay verify schema validation, rejection handling, residuals, constraint outcomes and rank changes. Report all shortlist outcomes and route systematic surrogate exploitation back to review before making search generally available.

## Phase V3.4 · Pressure data and visualization feasibility

The existing pipeline saves panel coordinates, logs and point polars. It has no paired surface pressure labels. XFOIL documents `CPWR` as writing x and Cp. In a newly approved bounded pilot, add it after the single viscous `ALFA` and test its exact Windows 6.99 output against the corresponding `PSAV` panels. Establish row count, rounding, traversal, leading-edge split, endpoint handling and whether and how the output reflects viscous state. Reject stale or misaligned pressure files even when some values parse. Preserve all attempts and compare console convergence and polar eligibility with pressure-specific validity. Evaluate repeated runs and 320-panel sensitivity separately from 160-panel labels. The nose can extend past x/c zero and the trailing edge has a finite gap. Use each surface's normalized arc length from LE to TE for sampling and retain physical x/c and y/c for plotting. Identify branch and segment by ordered panels and geometry rather than assuming sorted x or matching two surfaces by x alone. [XFOIL reference](https://web.mit.edu/drela/Public/web/xfoil/xfoil_doc.txt) · [Geometry contract](PHYSICS.md)

Proposed cap is 24 primary solves, three fresh repeats and three higher-resolution diagnostics. Use four representative geometry families, all three sampled Re values and two angles per geometry/Re pair preselected across the span, including edge and low-Re cases. Use the installed binary and a separate output directory. Measure time, raw size, eligible-pair yield and failure concentration. Test both branches against coordinate fixtures, candidate resampling error and a force consistency check against the corresponding polar with documented coefficient conventions. Keep pressure integration distinct from total viscous drag. Estimate larger dataset requirements and CPU/storage from the pilot, with exclusion rates and versions recorded. Prepare a Level 1 geometry design with chord, camber, scale, angle, surface coordinate inspection and opt-in labeled conceptual flow for implementation in V3.6. A velocity field needs a separate genuine CFD dataset, mesh/reference conventions and independent validation. Keep it in research.

Exit criteria:

- A reproducible report contains all commands, configurations, hashes and panel/Cp correspondence, including every failure. Proposed feasibility floor is 20 of 24 primary cases with eligible paired pressure data, at least one eligible pair per geometry/Re combination, zero ambiguous alignments among accepted cases and pressure repeats matching at printed precision or a documented measured tolerance approved before scaling.
- Quantify 160/320-panel sensitivity, leading-edge and trailing-edge resampling errors, pathological cases, runtime and projected storage. Propose pressure MAE, high-percentile error and suction-peak limits relative to measured solver/resampling variation and intended use, and obtain approval before full data generation. Failure or inconclusive data ends this phase with a documented geometry-only path.

## Phase V3.5 · Pressure surrogate

Proceed after V3.4 approval and a frozen data budget and metric protocol. Use versioned XFOIL pressure datasets with canonical geometry groups and predetermined disjoint train/validation/test splits. Start with a compact multi-output MLP baseline for two fixed surface arrays. Compare a station-conditioned MLP or common-grid 1D alternative only if justified by data and validation. Freeze model choice before opening the test panel. The browser activates the pressure model on demand, verifies its version and bytes, and validates finite outputs and the expected shape. Use separate upper/lower curves on physical x/c with conventional inverted Cp axis, dimensionless units and declared display conventions for the nose and finite trailing edge. Show the section coordinate and branch on pointer or keyboard inspection. Clear old pressure on input changes and show missing data explicitly. Label rendered values **ML-predicted surface pressure coefficient**.

Exit criteria:

- Audit disjoint geometry IDs, complete source/config hashes, paired surface definitions, rejected-case provenance and absence of imputation in the eligible label table. Tests cover resampling, ordering and coordinate/pressure alignment from raw data to plotted values.
- Meet the approved V3.4 pressure thresholds on unseen geometries, with metrics per surface, nose and Cp peak, and report sample and failure counts by stratum. Test source vs. ONNX vs. production-browser parity within `1e-5` absolute Cp and output shape parity for fixed-golden designs. Record bytes and load/display latency. Test missing/failed outputs, axes, branch labels and lazy requests. If gates fail, release geometry tools with the report and no pressure UI.
